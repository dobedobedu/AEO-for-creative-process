# UI Spec - React Flow Grid Tree

## Overview
Use React Flow to render a left-to-right tree that visualizes the audit pipeline.

## Node types
- PersonaNode (large, top-left)
- TriggerNode (stage + sub-triggers)
- QueryNode (5 total)
- ResponseNode (4 per query; model-specific)
- InsightNode (final analysis)

## Layout
Column-based dashboard layout with collapsible panels and a KPI row.
- Top row: KPI v0.1 tiles (one per provider)
- Column 1: Persona
- Column 2: Trigger(s)
- Column 3: Queries
- Column 4: Responses
- Column 5: Insight

## Feature Kanban (Coverage)
- Single board with 4 visibility tiers: Blind Spot / Mentioned / Recommended / Preferred
- Category tabs (document-organizer style): All, Amenity, Activities, Schools, Nature, Villages, Builders
- Cards show only title + mention rate; click opens detail modal for example citations
- Vertical dividers between tiers instead of boxed columns
- Legend shows mention-rate bands (0–10%, 11–30%, 31–60%, 61%+)

Behavior:
- One column expanded by default; others collapsed to summary state.
- Clicking a column header expands it and collapses others.
- KPI tiles are global (not per-persona) and update as responses stream in.

## Interactions
- Click node -> open side panel with details (raw text + metadata)
- Response nodes show status: queued / running / done / failed
- Insight node shows progress when analysis is running
- Query generation step includes an OpenRouter model selector (default deepseek/deepseek-v3.2)
- Add \"Generate with DeepSeek\" button for persona -> queries
- Show raw response text and citations in a results panel
- Show progress as completed/total calls
- Add \"Analyze with Gemini 3 Pro\" button
- Insights section shows narrative + charts + blind spots
- Insights section shows multiple variants (Flash vs Pro; consultant vs hypothesis)
- Runs execute with one lane per provider in parallel
- Show run history with ability to load prior runs
- Allow response selection (include/exclude) before analysis
- Add model tiles that summarize citation share, mention rate, and domain diversity per provider
- Columns collapse/expand to preserve screen real estate
- KPI tile “See domains” expands the selected tile and collapses others
- Replace expand text with shadcn icon button (lucide)

## States
- Draft: nodes are placeholders
- Running: response nodes update as each model completes
- Complete: all nodes show results; insight node shows charts

## Required data for rendering
Each node requires:
- id, type, label
- status (optional)
- data payload (query text, response text, citations, etc.)
- selection metadata (included/excluded responses for analysis)
- model tile metrics (citations, mention rate, unique domains)
- KPI expansion state (selected provider, expanded domains list)

Edges are generated by id relationships:
- persona -> triggers
- triggers -> queries
- queries -> responses
- responses -> insight
